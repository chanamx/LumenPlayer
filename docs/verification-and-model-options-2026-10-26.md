# LumenPlayer：状态复现、扩展实测与字幕模型交付核验

记录日期：2026-10-26，Windows 本机验证。模型下载、安装实验、项目临时文件和输出保存在 `D:/LumenPlayer/build/verification-20261026`。最终核对的 28 个原有源码、发布与用户数据文件全部保持原 SHA-256；正式分发及安装包没有被替换。

本轮的重点是先检验可行性与实际表现。新增模型尚未接入正式界面，候选安装包尚未集成下载入口。报告中的模型测量与完整播放器运行测试分别说明，避免把独立识别探针的内存当作整机播放内存。

**一、对前次静态判断的更正。**

前次“现代软件解码会显示成系统解码器”的判断错误，现撤回。`MpvBackend::IsCompatibility()` 已在头文件中覆盖并返回 true。当前生产源码的原生运行测试实际使用现代核心、软件解码、gpu-next 输出，设置页显示“当前：软件播放 · FFmpeg 兼容解码”，未复现所指误标。

CC 状态问题已复现。真实 ASS 字幕轨开启时，gpu-next 输出图中有红色、定位的字幕；关闭轨道后字幕消失。但底栏 CC 区域对比的 3876 字节 RGB 完全一致，均未反映该轨道的实际开启状态。现有激活条件仅检查本地字幕条目和实时字幕条目，遗漏现代核心内嵌轨道状态。

这些结论来自调用当前生产播放、绘制和控制函数的原生测试窗口，使用当前发布 DLL；它们没有被描述为独立发布 EXE 的鼠标操作。Computer Use 能找到隔离发布 EXE，但重试后仍报 `FrameArrived timed out: timed out waiting on channel`，因此真实鼠标选文件流程尚未完成。

将魔搭下载权重与匹配词表放入隔离安装目录后，生产字幕路径实际识别了正在播放视频的 PCM，并在关闭后卸载 ORT。该步骤验证了“下载来的模型可用”，没有将文件哈希相同单独当作播放识别已通过。

候选无模型安装包为 63,604,474 字节（约 60.7 MiB），当前正式安装包为 186,231,990 字节（约 177.6 MiB），实际减少 122,627,516 字节，约 65.85%。它仍使用当前发布 EXE，不含 ONNX/ORT 权重，正式安装包没有被替换。

安装实验发现：若词表随安装器管理、权重后来另行下载，卸载时会删掉词表而留下权重。发布方案需要把模型、词表、版本记录作为一套管理，并明确卸载时的保留策略。候选包尚没有图形下载按钮，不能当成已完成按需下载功能的正式版本。

建议的产品流程是：首次开启识别时选择语言与模型，显示下载大小；允许后台下载和取消；完成完整性检查后再启用；失败保留普通播放和已有模型。下载来源按同一模型身份回退，不能仅凭文件名在不同模型之间替换。权重许可应独立于 Sherpa 运行库许可核对；当前转换仓库指向的原始中文模型卡需要登录查看条件，本轮没有代替用户接受条款。

**四、资源相近的候选确实存在，转写与翻译需要分别选择。**

下表是本机实际进程测量，CPU 推理限制为一个线程、16 kHz 单声道、每 200 ms 按真实播放速度送音。RTF 是识别 CPU 时间除以音频时长，数值越小越省 CPU。稳定内存为识别探针的私有内存，包含该进程运行库，不包含播放器的视频、界面、GPU 和播放缓冲。延迟从模型就绪后文件起点计时，受片段起始静音和内容影响；不同语音之间不能直接视为纯算法延迟排名。

上述 Kroko、SenseVoice、Whisper 和旧 Moonshine 均用当前播放器固定的 Sherpa/ORT DLL 测量。流式模型按实际流式调用；离线模型采用不重叠的四秒分段，未将其包装成“原生流式”。四秒截断会损伤词句完整性，完整句子对照另行保留，不能仅凭分段输出判定模型本身的完整准确率。

英语两段带上游参考文本的语音共 66 个参考词，Kroko 在本轮规范化下为 5 个词编辑，约 7.6%；其中包括词形/拼写切分差异。法语三段带参考文本的语音共 36 个参考词、8 个编辑，约 22.2%，涉及专名及词形错误。三轮相同输出只证明重复性；这些很短的片段不构成总体准确率基准。日语、德语缺少本轮独立人工参考，不虚构 CER/WER。

德语测试还发现接入条件：直接复用当前 CTC 的 0.8 秒结尾补齐会漏掉末词 `zwei`；改为 2 秒后，三轮都输出完整句子。因此模型目录之外还需要正确的模型类型、分词方式、端点和结尾处理。直接改文件夹名称不能完成接入。

Kroko 的转换仓库指向 [Banafo 原作者](https://huggingface.co/Banafo/Kroko-ASR)，作者将社区权重描述为 CC-BY-SA，不能将引擎 Apache-2.0 自动视为权重许可。旧 Moonshine 日语属于带受限商用条款的 Community License；新版日语流式则在当前官方目录中列为 MIT。具体发行版本与许可应一并固定。

**六、中英互译的结论。**

双语或多语 ASR 负责把各语言的语音转成原语言文字，不等于互译。Whisper 的 `translate` 任务只以英语为目标，不能覆盖英语到中文。[Whisper 官方说明与实现](https://github.com/openai/whisper)。

本轮 tiny 的四秒分段中译英在三轮都出现明显错误：原语音的欢迎使用实时字幕内容，被译成包含 `10,000,000,000,000` 的文本。为排除固定分段造成的影响，又做了三轮完整 8.825 秒语音对照，仍出现 `It is easy to use 10-10 purpose flour` 等明显错译，约 10.2 秒才给出整句。不能把这组配置作为“不拉垮”的默认翻译方案。这并不证明所有 Whisper 规格或所有翻译模型都不可用。

完整句子的补测也验证了分段影响：日语旧 Moonshine/SenseVoice 在完整句子上给出更连贯的文字，首次结果分别约 7.59/8.10 秒；新版日语流式对相同 7.2 秒语音约 1.26 秒已有非空输出。因而不把四秒硬切的碎片全归咎于离线模型准确率，同时也不将整句吞吐率误称为实时字幕延迟。

英译中可考察 [Helsinki-NLP/opus-mt-en-zh](https://huggingface.co/Helsinki-NLP/opus-mt-en-zh)，中译英可考察 [opus-mt-zh-en](https://huggingface.co/Helsinki-NLP/opus-mt-zh-en)；两者有对应 [英译中 ONNX](https://huggingface.co/Xenova/opus-mt-en-zh)、[中译英 ONNX](https://huggingface.co/Xenova/opus-mt-zh-en) 转换。它们属于额外文字翻译阶段，需要分词、句子提交策略和独立解码接入。本轮尚未测量该两阶段方案的总内存、总 CPU 与字幕延迟，不宣称其已经达到现有中文识别的资源档位。

**七、证据、失败记录和未覆盖项。**

早期准备阶段曾同时编译与生成 4K 素材，主机提交内存耗尽，出现 `0x800705AF`、编译器分配失败与 x265 分配失败；该批结果未作为播放器或模型性能结论。恢复后重负载任务改为串行，并对识别和持续播放子进程加入实际提交内存监控、512 MiB 余量停止和超时限制。没有调整系统分页文件，也没有关闭无关用户应用。

另外保留了测试准备失败：第一版多语探针配置把部分 22.05 kHz 音源当成 16 kHz，且给 BPE 单位缺少相应热词词表；规范化采样率并改用无热词的默认单位后才进入正式重复测量。一次控制台 GBK 不能打印法语字符，原生 UTF-8 JSON 实际已成功，最终统计从独立 JSON/进程退出记录恢复；没有把日志编码错误当成模型失败。取消测试的首次失败来自隔离目录缺少本地输入文件，补上明确存在的输入后重新通过，原失败日志保留。

英语 20M、小型中英双语和旧版法语 Zipformer 的部分下载在本机超时或长度不符，未纳入已实测模型排名。被拒绝的半文件不会成为已安装模型。Computer Use 截图服务故障、物理 HDR/AVR、真实屏幕阅读器、跨屏 DPI、正式系统快捷方式/注册项和更多真实长片环境，仍属于未完成范围。

**八、据本轮结果建议的接入顺序。**

1. 中文保持现有识别模型，先实现可取消、有校验、失败不影响播放的按需下载；固定上述权重与词表配套，正式安装包移出权重后再发布。
2. 日语优先接入新版 Moonshine tiny streaming；当前 ORT 已有实际兼容证明，资源与出字延迟符合继续接入的门槛。德语优先考察同系列流式 tiny，Kroko 德语可保留为更省 CPU 的另一选择。
3. 低占用纯英语优先 Kroko streaming。新版 Moonshine 英语可以作为较早出字、CPU 代价更高的选择，不能不加区分地统称“更轻”。
4. 法语 Kroko 资源合适，但本轮短参考样本的错误较多，先保留实验候选；还没有足够证据把它评为已达到质量门槛的默认字幕模型。
5. SenseVoice 可以提供中英日等多语转写选项，但要接受分段/句尾等待。Whisper tiny 能覆盖更多语言，本轮没有证明它同时满足中文质量、翻译质量和现有低延迟要求。
6. 双向翻译单独作为“识别＋文字翻译”能力验证。当前已找到两方向的 OPUS-MT 候选，但缺少本机两阶段总资源与延迟证据，不将其提前列为已达标功能。

以上是接入建议，正式版本仍维持现有中文模型；本轮未修复 CC 指示、未修改正式播放器功能、未把 QA 包推广为正式发行。当前源码、发布 EXE、分发清单和原有设置/列表共 28 个基线文件核对通过，测试启动的隔离播放器已关闭。
