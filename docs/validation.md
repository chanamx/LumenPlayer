## 实际修复

1. 音频分段写入会继续读取正确的数据位置；音频设备操作互斥，暂停保留待播数据，解码预读受到限制。
2. 定位使旧样本失效，丢弃目标前的音视频，等待目标画面后恢复播放时钟与声音。修复解码时间戳超过容器时长造成的片尾无限等待，以及短音频末尾预览状态无法释放的问题。
3. 切换后端前停止并等待字幕采集线程；修正速度状态、硬件重绘、软解回退、播放结束后的行为。
4. 实时字幕模型在后台加载；关闭字幕时释放模型和原生库缓存；识别队列等待改为条件唤醒；跳转后重置识别时间线。
5. 修正全屏状态更新顺序、多显示器最大化坐标、缩放配置、设置面板溢出、文本越界及过小滑杆命中区域。
6. 统一悬停、焦点、禁用及提示状态；设置/帮助浮层隐藏被遮挡的控制条；加入可滚动设置、拖动字幕大小、快捷键帮助和键盘操作。
7. 空闲时按可见内容变化重绘，最小化时跳过界面上传；限制文字格式缓存，复用画刷，支持渲染目标重建与安全替换绘图缓冲。
8. 加入可复现构建、Windows 兼容性/DPI 清单、版本资源、日志轮转和回归脚本。保留现有依赖和全部识别资源。

## 性能记录

同一目录、同一 INI，原版和优化版交错各运行 3 次；每次进入消息循环空闲后再等待约 1 秒，采样约 3 秒。本表为各组中位数，原始值位于 `test/results/idle-comparison.json`。

| 指标 | 原版 | 优化版 |
| --- | ---: | ---: |
| 播放器 EXE | 1305.709 KiB | 401.500 KiB |
| 3 秒空闲 CPU 时间 | 0.344 秒 | 0.016 秒 |
| 空闲工作集 | 34.840 MiB | 36.723 MiB |
| 空闲私有提交量 | 15.656 MiB | 20.227 MiB |
| 启动进入消息循环空闲的耗时 | 171.476 ms | 185.286 ms |
| 空闲句柄数 | 379.000 个 | 377.000 个 |

空闲 CPU 时间中位数降低约 **95.5%**；EXE 缩小约 **69.3%**。空闲内存略增，启动样本存在波动，不能据此认定启动显著加速。启动指标是 Windows 进程进入输入空闲的时间，不等同于首帧视频时间。

本次优化版完整回归中，开启字幕后的私有提交量为 **897.82 MiB**，关闭字幕后为 **44.69 MiB**。这是同一个测试进程的开启/关闭测量，私有提交量不等同于物理工作集，也不是与原版峰值的对照实验。模型加载期间 UI 调用返回耗时为 **0.03 ms**，模型仍需要后台加载时间。

以下为此次回归的单次流程测量，不能当作稳定基准：

- `METRIC software_audio_open_ms 332.87`
- `METRIC software_video_open_ms 118.57`
- `METRIC software_video_eof_wait_ms 3292.79`

默认计算线程配置依据 [OpenBLAS 官方运行时变量说明](https://www.openmathlib.org/OpenBLAS/docs/runtime_variables/)，只设置本进程未被调用者显式配置的线程默认值。定位前置解码的行为参考 [Microsoft IMFSourceReader::SetCurrentPosition](https://learn.microsoft.com/en-us/windows/win32/api/mfreadwrite/nf-mfreadwrite-imfsourcereader-setcurrentposition)。

## 界面渲染证据与边界

`test/results` 中保存欢迎页、设置页、小窗口及滚动后的设置页、150% 缩放、快捷键帮助、字幕与控制条的 PNG。它们来自播放器自己的 Direct2D 分层窗口缓冲，**是离屏 UI 渲染，未包含媒体视频像素，也不是真实桌面点击截图**。

桌面截图工具两次超时，未完成真实鼠标点击逐项验收。自动测试直接调用原生输入处理及窗口消息，覆盖其逻辑和渲染。没有做人工音质/唇音同步判断、真实多显示器拖动、屏幕阅读器验收、数小时长片压力测试，或全部系统/显卡/编码器组合验证。

外部 CatsXP SODA 路径保留并增加兼容布局检查及非阻塞管道退出，但未对真实浏览器进程进行注入/识别联调。本轮已验证的是随附 Vosk 中文引擎。其他媒体容器与编码取决于系统组件。

原始日志中的 `actual_hw=1` 表示播放器使用 MFPlay/EVR 后端；没有通过 GPU 分析工具验证实际解码单元的使用情况。
