# Caption startup Implementation Plan

**Goal:** 缩短开启实时字幕时打开视频到真正释放播放的等待，保留当前 Zipformer CTC INT8、单线程识别、暂停/取消/换文件逻辑及关闭后的资源释放。

**Architecture:** 先分离运行库加载、模型会话创建、流创建与媒体准备的实际耗时。优先复用 ONNX Runtime 自带的离线优化/ORT 序列化能力，将重复图优化移出用户启动过程；仅在同一原生 sherpa C API、识别结果、延迟与资源验收通过后采用。必要时让已经授权的模型初始化与媒体准备重叠，不增加后台常驻模型。模型源件和现有 1.4.0 程序保留恢复依据。

**Tech Stack:** C++17 / sherpa-onnx 1.13.8 / ONNX Runtime 1.28.2 CPU / 本地固定模型及现有 PowerShell 原生测试。

## Options and decisions

1. 优先测试离线图优化及 ORT 模型：直接减少会话初始化的重复工作，模型无需降级；需验证平台兼容、结果一致与安装体积。
2. 将初始化与视频打开并行：只能节省两者可重叠部分，作为测量后的小幅补充，不用后台常驻掩盖首次加载时间。
3. 改模型、降低识别参数或长期驻留：本轮不采用，避免改变当前效果与关闭后的内存行为。

## Steps

1. 备份当前源码、1.4.0 EXE、用户配置及验收证据；建立原生启动分段测试和正式进程等待基线。
2. 使用同版本 ORT 生成候选优化模型，比较原始 ONNX、优化 ONNX 和 ORT 的原生 sherpa 会话创建、首条文字、CPU/内存与识别文本。
3. 只接入有实测收益的最小方案，保留失败处理和旧格式兼容；更新固定模型打包、来源/散列与恢复脚本。
4. 针对首次加载、再次启动、就绪后换文件、加载中暂停/取消/换文件、无音轨、路径字符与关闭释放做回归；运行完整原生检查。
5. 构建并安装补丁版本，用实际 EXE 交错对照 1.4.0 的打开到字幕就绪/释放播放时间，记录首次与重复运行边界、内存和磁盘开销。
6. 更新 README、当前验收与 manifest，验证用户配置和文件散列，清理仅本轮生成的冗余副本。

## Completion

2026-10-19 已交付 1.4.1：使用原生 ORT 1.28.2 CPU 扩展图优化预生成模型，保留原始 ONNX，运行目录模型增加约 0.84 MiB。两段中文的原生文本和首次文字所需音频量一致；完整回归 651 项，68 条视频组合及三种正式 EXE/路径烟测通过。1.4.0 / 1.4.1 正式程序交错各四次，播放等待中位数约 3.68→2.09 秒，减少约 43%；首轮新版视频库准备出现额外延迟，原始样本保留，不能保证所有首次冷开都更快。稳态内存略降，启动峰值工作集升高；内存映射及映射初始权重专测未消除此峰值，因此没有增加正式加载配置。完整结果与边界见 docs/caption-startup-validation.md。
