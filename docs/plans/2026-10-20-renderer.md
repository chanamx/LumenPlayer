# GLSL, HDR and media capability implementation plan

**Goal:** Preserve the existing player interactions, HLS and real-time captions while giving video a high-bit-depth, color-aware GPU renderer and verified format capabilities.

**Architecture:** Reuse libplacebo's native D3D11 backend, the rendering library used by mpv gpu-next. Pass original decoded AVFrames to it before BGRA quantization. Use the existing FFmpeg/WASAPI clock and PCM tap; offer actual D3D11VA decoding with software fallback in the same pipeline. Retain the native system path as an emergency fallback. Keep display HDR state user-controlled.

**Tech stack:** C++17, Win32, FFmpeg 9, libplacebo 7.377.0 (pinned to the mpv reference's upstream commit), D3D11/DXGI, WASAPI.

1. Back up the installed 1.7.0 source, EXE and configuration. Verify upstream package hashes, dependency imports, licenses and exact API headers. Read mpv and MPC Video Renderer documentation; record differences between rendering algorithms and physical output support.
2. Add one renderer module. Initialize lazily for video, upload original YUV/10-bit frames, handle BT.601/709/2020, range, PQ/HLG and metadata. Fit to the video rectangle, use mpv-equivalent default scaling/color algorithms, dither to actual output depth, and use HDR output only when the active monitor and Windows support it. Provide SDR tone mapping otherwise. Handle resize, pause redraw, seek, shader errors and device loss.
3. Add mpv-style GLSL hook selection, disable/reset and clear runtime status in existing menus/settings. Validate shader input size and failures. Preserve native keyboard/mouse/sidebar behavior.
4. Unify video decoding with software and D3D11VA selection, preserving user pause/rate/position during switches. Never identify an unverified MFPlay path as confirmed hardware decoding. Preserve live HLS and submitted-audio captions.
5. Prefer the actual endpoint's supported multichannel PCM layout; downmix on stereo devices. Probe AV1 decode and audio codecs/layouts; report Atmos metadata/object rendering/passthrough separately from ordinary PCM decode. Do not infer physical Atmos support from FFmpeg decoder availability.
6. Add runnable native checks and color/format fixtures, GPU readback comparisons, malformed shader and recovery checks, AV1 and multichannel tests. Run existing seek/caption/UI/HLS regressions and release smokes against the final EXE. Preserve exact user data at install, then regenerate the manifest and validation report and preview verified cleanup.

Acceptance limits: The same rendering library is not proof of identical defaults. Compare selected mpv defaults and rendered pixels explicitly. This host's SDR display/stereo endpoint cannot establish real HDR monitor output or Atmos speaker acceptance; those boundaries must remain explicit.
