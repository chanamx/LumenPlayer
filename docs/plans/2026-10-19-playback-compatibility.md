# 字幕就绪后播放与软硬解兼容性实施计划

**Goal:** 开启实时字幕时，打开媒体先准备解码与首帧，等模型及采集就绪后按用户意图播放；同时修复已识别的播放兼容性、性能和错误恢复问题。

**Architecture:** 保留现有 MFPlay/EVR 系统路径与 SourceReader/WASAPI/GDI 软件路径。播放暂停屏障放在 Player 统一入口，区分实际播放与等待后的播放意图；模型在切换媒体时复用。直接改进现有格式协商、帧复制和音频线程，不新增解码框架。

**Tech Stack:** C++17、Win32、Media Foundation、WASAPI、现有 sherpa-onnx CTC。

## 1. 保留基线与接口核对

- 备份 1.2.0 源码、程序、用户当前配置及已有验收证据。
- 使用 Context7 与 Microsoft 官方文档核对 MFPlay 异步就绪、SourceReader 输出变化/行跨度、WASAPI 共享模式与事件驱动要求。

## 2. 字幕启动和媒体切换

- src/player.h/.cpp：向 Open 传入是否自动播放；两个后端准备阶段不提前输出声音。Player 保存等待状态与播放意图，统一处理播放、暂停、单击/空格和回退。
- src/main.cpp：字幕开启且媒体有音轨时，等待识别器与 tap 就绪；加载失败/取消时释放等待，手动暂停不被自动恢复覆盖。
- 切换文件时停止旧 tap 并重置识别代次；保留正在加载或已经就绪的模型，避免重复冷加载与等待旧线程阻塞操作。
- 无音轨媒体直接播放，不启动无用的识别器，不关闭全局字幕偏好。等待提示与播放按钮反映用户的播放意图。

## 3. 软硬解适配与稳定性

- 硬件优先直接尝试系统播放路径，避免用全局 MFT 枚举结果排除可工作的 DXVA/EVR；等待媒体就绪事件而不靠先播放获取尺寸。
- 去掉打开前重复 SourceReader 探测，保留原始文件路径元数据以改善源识别。
- 软件路径读取实际输出尺寸、像素布局、行跨度、色彩矩阵/范围和像素宽高比；响应格式变化，验证缓冲范围，修正倒置/填充帧与 NV12 转换。
- 音频统一协商常见 PCM 格式并支持系统转换，正确辨认 extensible 子格式；初始化失败使用新 AudioClient 重试。
- 使用事件驱动共享音频输出并保留兼容轮询回退，停止时可立即唤醒。处理缓冲写入失败和设备失效，在默认设备变化后有界重建并保留位置/播放意图。
- 解码错误安全停下并给出反馈，避免失败线程忙等或只走时钟却不输出。

## 4. 验证与交付

- test/regression.cpp：字幕等待期间时钟与声音不前进、就绪后从头播放、取消/暂停/换文件、模型复用、无音轨、软硬解初始暂停和回退状态。
- 用 FFmpeg 在 test/results 生成小型格式样本，验证系统实际支持的格式和不同音频采样/位深/声道、像素尺寸及动态格式；不把扩展名或安装了 codec 等同于实测可解码。
- 真实帧缓冲测试验证 padded/bottom-up RGB、NV12 色彩/边界与动态尺寸；模拟错误/设备变化验证恢复，不声称做过物理热拔插或 GPU 分析。
- 完整回归、正式版构建安装、字幕就绪后播放烟测、INI 散列保留、版本/报告/manifest 更新。
- 本项目无 Git 仓库，使用可回滚文件备份，当前会话直接完成实施与验证。

## 完成记录

- 1.3.0 正式程序已构建并更新至 dist，安装前后的用户 INI SHA-256 相同；1.2.0 完整变更基线保留在备份 ZIP。
- 全量原生回归 258 项断言通过，正式 MP4 进程验证 0 秒等待、模型和 tap 就绪后释放播放、加载期间响应及正常退出。
- 17 个输入按两种播放偏好共 34 组：27 组实际解码，HEVC/Ogg-Opus 与损坏输入各两组安全拒绝，TS 软件路径间歇格式失败且安全停止。系统 TS 通过，不宣称软件 TS 稳定支持。
- 未修改正式 EXE 的隔离性能对照每版 4 次；额外源码插桩诊断每版 4 次记录真实送帧、媒体时间推进及 CPU/帧。新版本样本维持约 30 fps，旧版约 23 fps；总 CPU 时间增加而 CPU/帧降低，具体值和方法保留在验收报告，避免把工作量变化误判为占用改善。
- 限制：音频失效和设备 ID 改变为注入测试，实际恢复使用本机真实端点；未做物理热拔插、全部 GPU/驱动、长片、HDR 或外部浏览器 SODA 联调。
