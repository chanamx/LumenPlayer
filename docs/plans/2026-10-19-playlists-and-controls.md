# Playback controls and playlists (1.6.0)

Implement the user's decoder, captions, keyboard, focus and rapid-click corrections together with persistent playlists. Keep native Win32 rendering, existing codecs and recognition model. Back up the 1.5.1 source and executable first.

1. Preserve position, volume, captions and play/pause intent when switching the current media between the Windows hardware-preferred pipeline and software decoding. Prepare a replacement before discarding a working backend; retain the current backend on an unsupported switch. Report the Windows route honestly because MFPlay does not expose the selected decoder's GPU utilization.
2. Settings caption toggles never choose playback state. Hold keyboard Right Arrow for configured temporary speed; a short tap advances five seconds. Key release, focus loss and cancellation restore the original state. Keep the existing left-mouse hold gesture.
3. Handle the second button-down delivered as WM_LBUTTONDBLCLK for playback controls. Remove the rectangular progress-slider hover/focus outline, keeping focus visible on its thumb. Verify unsaved captions are RAM-only and explicitly clear them during shutdown; exported files remain user data.
4. Add a playlist panel with a main list, named folders, multi-file addition, directory import, removal, previous/next dedicated controls and EOF advance. Browsing folders does not change the playing queue. Persist paths, ordering and the selected folder in one bounded UTF-8 file using atomic replacement; never modify or delete media files. Provide keyboard selection/activation and usable small-window/DPI layouts.
