# 2.1.1 实时字幕恢复验证

本次处理“模型已启动、字幕不出现”的实际反馈。继续使用原中文 Zipformer CTC INT8 `.ort` 模型，未替换模型权重、识别算法或推理库。模型安装、删除及多语言选择继续保留。

## 已复现的原因

在用户当前的课程片源上请求跳到 485 秒，播放核心实际从约 490 秒恢复，并报告 `seeking=false`；应用仍要求实际位置必须落在目标前后 0.5 秒内，持续保留自身的 `seeking=true`。同一状态又阻止当前播放连接的 PCM 进入识别器，因此可以同时出现“模型启动成功”“采集已就绪”和零字幕。

修复前，独立进程复现得到 `failedPosition=485`、`failedSeeking=true`，中途开始采集的测试音频帧数为 0。已运行识别后再跳转的测试同样未能结束等待。诊断记录在 `build/caption-recovery-20261027/test/results/backend.log`，包括目标 485 秒、核心实际约 492 秒、命令确认成功、核心 `seeking=0` 的对照。

`src/mpv_backend.cpp` 现在同时接受播放核心的 `MPV_EVENT_PLAYBACK_RESTART` 作为跳转完成依据。只接受当前跳转命令确认后的事件，并保留请求代次检查，避免被旧请求释放采集。接着采用核心实际位置恢复界面与 PCM。该修复作用于所有识别模型共用的播放音频路径。

## 真机测试

测试使用本机实际播放核心、WASAPI 音频输出、原中文模型及生产界面绘制函数；各个识别进程串行运行，带已有内存与超时保护。`test/caption_recovery.cpp` 通过 `build.ps1 -Target CaptionRecoveryTest` 编译；参数为片源、独立结果目录和跳转秒数，可追加 `--pcm-only`、`--active-seek` 或 `--stress-seek`。

| 场景 | 观察结果 |
| --- | --- |
| 原版、真实片源从头播放 | 原中文模型识别并绘制“同学们大家好欢迎来到江苏省名师空中课堂”，说明模型本身能够工作 |
| 修复后、真实片源跳到 485 秒，只核验音频 | 跳转正常结束，5 秒内收到 214,016 帧有效音频；实际位置约 495 秒 |
| 修复后、识别运行中跳到 485 秒 | 收到 694,272 帧音频，产生完整中文句子并绘制字幕 |
| 修复后、模型加载时跳到 485 秒 | 收到 673,792 帧音频，产生完整中文句子并绘制字幕 |
| 修复后、暂停时连续发送 20 次跳转，再确认最终位置 | 暂停保持；暂停期间不继续送入识别音频；旧临时文字清除；继续播放后重新生成并绘制中文字幕 |
| 修复后、原有短中文测试片从头播放 | 原模型继续生成字幕，原有路径通过 |
| 正式 2.1.1 可执行程序 | 输入就绪、实际 gpu-next/WASAPI 输出、原模型与采集启动、生成两条字幕、正常退出均通过；测试程序设置和列表按原字节恢复 |

中途播放识别内容包括“探讨它的含义我们还要知道如何来表示一个集合……研究他们的运算”。各次原始报告、SRT 和界面绘制结果位于新验证目录，没有将先前模型列表测试的通过次数当作本次字幕恢复证明。识别结果可能含一般识别误差，本次验收针对音频恢复、文字生成和绘制。
