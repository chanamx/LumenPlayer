# 实时字幕模型管理与 2.1.0 发布验收

本轮将此前的候选与下载源研究接入播放器：用户可以选择识别模型、翻译模型、翻译目标及下载源，自行下载安装、取消、切换和删除。正式运行目录已更新，安装包不携带语音或翻译模型权重。已有设置、播放列表及旧中文模型保留。

原生软件测试及隔离安装流程通过；独立程序的完整鼠标操作尚未完成验收，原因与范围单独列在文末。测试断言数量不代表独立片源或人工操作次数。

## 交付物与使用

- 正式入口：`dist/LumenPlayer.exe`，版本 2.1.0。
- 安装程序：`build/caption-model-manager-20261027/installer/LumenPlayer-2.1.0-x64-setup.exe`，68,278,006 字节，约 65.11 MiB。
- 安装包 SHA256：`ac5345e4cfe239acb001b8d628cb6b09cd21ac191419094913aea93ba5c0c55c`。
- 模型目录与全部固定来源：[`resources/caption-models.json`](../resources/caption-models.json)。程序采用对应的编译内置目录，每个文件的大小、SHA256 与版本地址均固定。
- 最终证据入口：`python test/finalize_caption_manager.py --check-only`，核对本轮运行时、安装包、测试记录、源文件与模型来源文件。记录位于 `build/caption-model-manager-20261027/final-validation.json` 及 `evidence-manifest.json`。
- 恢复包：`build/caption-model-manager-20261027/recovery/before-model-manager.zip`；此前研究与失败现场保留在各自原目录。

按 G 打开设置，选择“模型与语言 · 下载 / 管理”。窗口较小时可向下滚动设置。选中一个模型及来源，点“下载安装”；安装完成后选择“用作识别”或“用作翻译”。翻译目标可选中、英、日、德、法。最后按 C 开启实时字幕。仅下载不会自动启用。

“仅显示原文”关闭翻译选择。删除操作需要确认，会先停止使用所选模型并等待释放；应用只删除登记的模型文件及对应未完成下载，保留未知文件。安装包升级和系统卸载均保留用户自行安装的模型；模型可在卸载软件前通过列表主动删除。系统卸载沿用既有设置与播放列表清理策略。

## 下载与删除行为

后台一次安装一个模型，显示真实任务阶段、已收到字节及安装结果。取消中断网络请求，保留可续传部分；服务器忽略 Range 时重新写入，错误区间响应拒绝拼接。文件大小和 SHA256 校验完成后，整个模型及辅助文件一次性启用。

显式选择来源时，模型主体从该来源获取；缺少同版本辅助文件时，使用其唯一已核验来源。中文魔搭方案中的词表来自 HF，选择该来源时界面会说明。GitHub 中文方案使用完整固定校验值的压缩包，运行组件也核对完整归档及解压成员。

网络使用标准证书验证与 HTTPS。403、429、503 会停止并提示稍后重试或手动选择来源，不循环尝试绕过限制。安装和删除检查目录链接与路径边界；未登记目录及无关文件不被清理。使用中的模型通过应用先停止、释放，底层也拒绝直接删除。

本轮发布下载器实际完成了两条公网传输：

| 公网安装 | 本轮结果 |
| --- | --- |
| Moonshine 官方日语 Tiny，全部 8 个文件，32,319,961 字节 | 下载、原生 SHA256 校验和安装成功，约 9.06 秒 |
| 魔搭中文模型主体 + HF 固定词表，共 162,311,515 字节 | 下载、整包原生校验和安装成功，约 92.90 秒；随后通过同一管理组件删除，并确认不可再作为已安装模型使用 |

其余来源沿用前轮固定版本和完整文件核验记录。公网可达性受地区和网络环境影响。播放器集成测试中的中文、日英及翻译模型安装使用经过校验的本地缓存，验证缓存、安装、加载与运行链路；这些缓存测试不计作新的公网下载。

## 本轮实际运行测试

主机为 i5-7200U、2 核 4 线程、约 7.89 GiB 内存。编译、编码与推理串行执行；推理设定时间与提交内存边界，保留每次成功及失败的日志。

| 测试 | 结果 | 证明范围 |
| --- | ---: | --- |
| 原生模型目录与传输故障 | 68 项断言，通过 | 固定模型寻址，真实 HTTP 传输，取消续传，坏哈希，缺辅助文件，404 回退，429 停止，错误区间，实际归档解压，使用中保护及删除保留无关文件 |
| 原生播放、字幕、翻译与既有布局回归 | 134 项断言，通过 | 实际 gpu-next / WASAPI 播放音轨生成中文、日语、英语字幕，SRT 导出，暂停无新 PCM，跳转代际重置，丢弃旧译文，双语 SRT，停止、卸载与删除 |
| 原生模型窗口组件 | 84 项断言，通过 | 真实 Win32 对话框和控件，7 行模型、中文 4 个来源项、日语官方来源、5 种目标语言、安装后选择状态、回调、键盘顺序、控件边界及删除选择同步 |

合计 286 项原生断言。原生窗口组件测试在测试进程内调用生产对话框过程和命令，使用正式模型管理组件安装真实日语包。它不包含桌面鼠标操作。

窗口布局检查包括 580×450、820×570，以及 1、1.5、2 倍布局缩放；既有设置页也生成多个尺寸和缩放的原生渲染图。这验证布局计算与控件边界，未替代不同物理显示器的真实 DPI 切换。小窗口设置中的模型入口已人工检查原生渲染结果。

此前 CC 状态问题本轮已修正并验证：实际选中内嵌字幕轨时，无需本地字幕数组也会高亮；关闭字幕显示或取消实际字幕轨后清除高亮。`cc-embedded-active.bmp`、`cc-embedded-off.bmp` 与对应断言保留在 `integration-results-5`。此前软件解码状态的实测复现范围见[原验证记录](verification-and-model-options-2026-10-26.md)。

识别输出仍有错误。本次完整日语句子的“写真”被识别为“シャンシー”；中文测试开头“你好”也发生同音错识。通过的连接、时间轴和关键词检查不代表准确率满分。日英更大样本、连续流、音乐与噪声测量继续引用前轮报告，未把本次少量片源扩称为广泛准确率验证。

实际英语播放经过 Moonshine Tiny → Hy-MT2 → 中文译文和双语导出已通过。例如原文中的 “Mr. Quilter is the apostle of the middle classes…” 保留在导出文件，译文输出“奎尔特先生是中产阶级的使者…”。改变播放代际后，已经发出的旧翻译任务不能再进入新字幕会话。

## 翻译性能与质量

发布翻译接口补测了两款模型的日→中、中→日、英→中、中→英，共 8 次完整请求。每次重新启动本地翻译服务，当前 Windows 文件缓存可能已热；以下时间包含服务启动，不是稳定运行后的逐句延迟：

| 模型 | 本轮服务重启后整句完成时间 | 本轮重要观察 |
| --- | --- | --- |
| Hy-MT2 Q4 | 约 6.81–8.33 秒 | 日中空调例正确保留“不要关闭”和“降低两度”；中日、中英、英中方向输出对应语言 |
| Index Q4 | 约 7.39–10.72 秒 | 日中空调例把“降低两度”译成“降低两次”；其余三例保留了相应否定和按钮次数 |

上述自动检查主要确认接口、语言、主题和停止流程，语义错误通过逐句查看记录。`passed` 不表示每句语义正确。Index 的单位错误已单独登记，不能因关键词存在而忽略。

前轮各 32 句稳定服务测试中，Hy-MT2 与 Index 的整句完成时间中位数约 3.8、4.3 秒，工作集约 1.2、1.3 GiB。播放器、语音识别与翻译共同运行的占用和时序还受媒体、CPU 竞争与系统缓存影响；这些单独模型数字不替代联合负载长期测量。

两款模型作为中配以上可选项提供，默认保持仅识别原文。模型准备或某句超时期间保留原文；队列最多等待两句，落后的旧句可跳过翻译。当前低功耗机型不能按轻量识别模型的实时性承诺译文跟随。

## CAT 下载已完成，未收录

此前未完成的 CAT-Translate 0.8B Q4 已续传完成：528,205,184 字节，完整 SHA256 为 `6de8e40b687eb2248727c8ad208c54af8c82ad52b415901859d5fcd7fd65bb4c`。测试对象为 mradermacher 社区 GGUF，原作者为 cyberagent；该结果不泛化为所有原始精度或其他量化版本。

原始模板与显式作者模板分别完成 16 句日英测试，共 32 次完整响应。整句完成中位数约 1.87 秒与 1.67 秒，资源较轻，但存在英译日仍返回英文、条件句丢失条件、重约时间变成时间区间等问题。确认 GGUF 模板与作者模板相同、强制使用作者模板并处理输出结束符后，质量问题仍然存在，因此本轮不加入可安装列表。

作者权重首发依据为 2026-02-02；较早的空仓库创建时间与之后的 README 维护日期均不当作新模型发布时间。此前质量不足的小型候选、重型识别方案，以及尚未实现当前原生推理接入的模型，保持研究记录，不混入本轮可安装包。

## 安装包与数据保留

正式包从通过 SHA256 核验的运行时清单复制 109 个文件，不从工作目录任意收集用户文件。安装包和精确展开内容均不含 `.onnx`、`.ort`、`.gguf`、`.safetensors`，不包含 settings、播放列表、cache 或 models。已有中文目录也不进入新安装包。

隔离 QA 安装程序使用正式包相同的 109 个有效载荷文件，另用独立身份、项目内目标目录，关闭系统注册项、快捷方式和安装后启动，以进行以下实际操作：

1. 新安装并逐一核验 109 个文件，确认无模型权重。
2. 放入经原生公网下载器安装的真实日语模型、旧中文 ORT 模型及辅助文件，以及测试用设置和播放列表。
3. 恢复升级前备份中的旧版 EXE，再运行升级安装；核验正式 2.1.0 内容、设置、列表、日语和中文模型均保持完整。
4. 运行实际卸载程序；确认程序及运行库、测试设置与列表按既有策略清理，日语、中文模型和未知用户文件仍保持相同 SHA256。

这是有效载荷和隔离生命周期验证，未验证正式安装身份下的系统快捷方式、注册项或所有历史安装状态。正式 `dist` 的原设置、播放列表在发布前后也保持相同 SHA256，已有中文模型内容保留。

最终发布清单中的 EXE / DLL 使用 XPRESS8K 透明压缩，逐一核对内容不变。该范围逻辑字节为 213,674,211，最终实际存储为 113,762,304 字节。最终重发布保留了未变化 DLL 的已有压缩状态，仅替换变化的程序；本次增量前后值见 runtime-storage.json。此范围不包含用户模型和其他目录，也不表示内存或播放 CPU 降低。

## 发现并修正的问题与验收边界

本轮实际测试发现并修复了两处阻断：模型 JSON 的临时对象生命周期导致目录读取失效；翻译运行包缺少 `llama-common.dll`、`mtmd.dll` 导致服务无法启动。分别增加固定目录寻址检查、实际 Windows 导入依赖检查，修复后重跑完整播放与翻译测试通过。早期失败现场保留，最终成功记录为 `integration-results-5`。

最终窗口状态审查另修正一处问题：删除翻译模型时，同步清空窗口保存的旧选择，防止随后改变目标语言又写回已删除模型。按 Ponytail 流程在现有刷新路径添加一处同步，补上两项回归；最终窗口组件检查为 84 项。发布程序重新构建，安装与升级卸载流程也重新执行。134 项播放验证使用对应的识别和翻译实现，删除选择修正由窗口组件专项验证。

通过 computer-use 枚举并启动了独立发布程序，也读取到主窗口可访问性树。但屏幕捕获多次返回 `FrameArrived timed out` 或 `window capture timed out`；重置客户端和用户确认桌面解锁后重试仍失败。快捷键输入后没有获得足以确认模型窗口操作的现场证据，因此完整鼠标下载安装、删除及实际视觉显示继续标为未验证。原生组件测试及生成的渲染图不替代这项验收。

测试窗口随后出现实际播放日志，已保留该窗口及新设置，不强行停止。自建翻译服务和各原生测试进程在各自测试后退出；过程审计记录留在最终报告中。

本轮未重跑所有历史网络协议矩阵，也未增加新的真实 HDR 显示器或 HDMI 对象功放验收，未完成数小时带翻译的联合高负载测试。这些范围继续保留边界，不从短片、文件哈希或断言数量推出普遍稳定性。
