# Lumen Player 1.5.0 交互与发布验收

日期：2026-10-19；平台：Windows-10-10.0.19045-SP0，本机 Intel Core i5-7200U、2 核 / 4 线程。

## 已交付的行为

- 在设置中开启实时字幕只暂停一次，不建立模型播放等待。模型在后台准备，用户可立即手动播放；完成后保留用户选择的播放或暂停状态。没有媒体时仍不加载模型。已开启字幕后再打开媒体、按 C 启动的既有起点等待策略保留，失败、取消、无音轨处理通过回归。
- 字幕实现改为 `src/captions.cpp/.h`。删除播放器的浏览器扫描、进程注入、管道通信、桥接构建文件和引擎选择 UI；正式目录移除 719,439 字节的原桥接 DLL。未访问或修改浏览器安装、配置或浏览器模型。保留旧 INI 的字幕开关键用于迁移，旧 `engine` 字段不再参与选择。
- 设置新增右键倍速开关和 1.25×–8× 倍率（0.25× 步进，支持拖动与键盘）。按住画面右键生效，松开恢复原播放/暂停；关闭开关不产生倍速动作。左键长按仍分段 2×/4×/8×。不支持原生倍速的解码器沿用跳帧快进，未新增软件音频时间伸缩器。
- 进度条拖动合并请求并预览实际画面。软件定位在现有解码线程上执行；新目标覆盖待处理目标，正常约每 160 ms 最多提交一次，解码慢时先等待、超时更新最新目标。对应画面就绪后通过正常音频输出预听约 160 ms；保持当前音量/静音。拖动期间暂停字幕采集，避免将预听片段写成正式字幕。松手、捕获丢失恢复原播放状态，最终请求覆盖旧预览；尾部跳转不误触发从头重播。
- EXE 和主窗口使用与现有蓝色播放标志一致的图标。保留 SVG、PNG 和 16–256 像素多尺寸 ICO 及重建脚本；原生资源加载测试覆盖 7 个尺寸。

## 启动速度检查

现有 ORT 与预优化 ONNX + 关闭重复图优化，各启动新进程 4 次，交错运行，保持 ORT 1.28.2、CPU 单线程、同一段音频。ORT 会话准备中位数 **1700.5 ms**，候选 **1655.5 ms**，差 **2.65%**；单次结果波动，候选未显示稳定的启动优势，因此保留现有模型文件和参数。这是原生会话对照，不是本轮 GUI 启动提速结论。测量期间用户原有播放器窗口正在播放，未强制整机空闲或冷缓存，微小差异不足以作发布替换依据。

实验峰值工作集 ORT **388.9 MiB**、候选 **229.3 MiB**；加载后私有内存 **221.7 / 210.2 MiB**，推理 CPU 中位数 **0.930 / 0.953 s**。候选的内存优势记录为后续评估线索，本轮未将其替换入正式包，也未进行它的跨机器或完整播放器验收。8 次识别文本及首次出现文字的音频位置一致。

## 验证结果

- **681 项原生回归断言通过**；覆盖设置状态持久化、非法倍率、键盘/鼠标/捕获、100%/150%/200% DPI 和小窗口滚动，字幕加载/取消/复用/失败/EOF、真实音轨识别及资源回收。
- 68 个媒体用例：66 个有效输入按预期解码，2 个损坏输入安全拒绝。软件与系统路径、旋转、 seek、EOF、音频恢复等原有兼容性通过。修正了 PowerShell 将损坏输入的 FFmpeg 标准错误诊断误判为脚本失败的问题，断言失败仍由退出码检测。
- 100 次连续拖动事件 **1.03 ms**，这是事件处理时间，非画面解码延迟。已验证拖动时实际帧时间、WASAPI 音频提交、短预听结束及松手/捕获丢失后的状态；没有通过人工听音或所有系统混音设备验收声音观感。
- 本轮回归就绪模型切换视频 **195.97 ms**，首次字幕 WAV **498.07 ms** / WebM **615.22 ms**；这些是本次本机样本，不能直接与不同负载的旧测试推断版本提速。
- 正式安装目录内的 H.264、HEVC 软件解码，以及中文/空格/特殊字符程序路径下的 WebM/Opus 三项启动验收通过；各位置 EXE 的 SHA-256 完全一致，依赖文件核验相同。窗口响应、模型/音轨就绪、起点等待释放和正常退出均核验。启动到模型/采集就绪分别为 2448.3 ms, 2420.5 ms, 3217.1 ms，不是严格冷缓存对照。用户关闭旧窗口后，已补验实际安装目录中的新版启动，并在退出后恢复用户 INI。
- WenetSpeech 单段回归识别文本保持一致；不能把单段结果当成模型榜单或整体准确率。随附模型、tokens、ASR/FFmpeg DLL 的散列与 1.4.1 一致。

## 文件和恢复

正式 EXE **455,168 字节**，之前 **454,144 字节**。完整运行包 **291.05 MiB**。EXE SHA-256：`13e1b203e3c2b89403d4fa0879705776c7f82b18606deedc370300eb5f88f9f8`。

用户 INI 与本轮开始备份、安装快照均字节一致。验收启动时允许应用保存新增默认项，测试退出后恢复验收前的配置，记录在每个 smoke 的 `configChangedDuringRun` / `configUnchanged`。备份 `build/backups/pre-interaction-upgrade-20261019.zip` 保存旧 EXE、INI、源码、脚本、原桥接及原发布记录，恢复不需要改动浏览器。

安装时采用同目录保留旧映像再替换启动文件的方式，保持原“视频.ts”窗口继续播放。用户确认关闭旧窗口后，已验证旧映像散列并删除 `dist/LumenPlayer.1.4.1.running`，正式目录仅保留新版程序；原 EXE 仍保存在压缩备份中。

本轮清理生成的候选模型、路径测试包、构建运行副本及退出后的旧程序映像，共 **736.24 MiB**；保留源模型、正式运行包、依赖、备份与结果。确切文件清单和散列见 `release-manifest.json`。

界面 PNG 来自播放器自己的 Direct2D 绘制缓冲，已查看常规、小窗口和 150% DPI 状态。未覆盖所有 Windows/GPU/驱动、完整磁盘冷缓存、数小时长片、物理音频设备热插拔、人工音质/唇音同步或全部桌面实点。未新增 FFmpeg GPU 解码或音频保调时间伸缩功能。

复验：`powershell -ExecutionPolicy Bypass -File test.ps1`、`python test/check_startup_headroom.py`、`powershell -ExecutionPolicy Bypass -File build.ps1 -Install`，以及三个 release smoke 脚本。图标可用 `python test/make_icon.py` 重建。模型离线优化依据：[ONNX Runtime 官方文档](https://onnxruntime.ai/docs/performance/model-optimizations/graph-optimizations.html)。旧版本报告为历史记录。
