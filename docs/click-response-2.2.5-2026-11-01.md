# LumenPlayer 2.2.5 画面单击响应调整

2.2.4 为避免双击先触发播放／暂停，将画面单击保留到整个 Windows 双击判定窗口结束。本机复现时系统窗口为 500 ms，因此单击有明显等待感。修改前的新原生探针在 200 ms 判定点仍未收到播放／暂停命令，复现日志及 2.2.4 构建已保留。

本轮将画面点击的应用判定窗口改为 `min(200 ms, 系统双击时间)`。定时确认单击与接受画面双击使用同一个函数，不修改系统鼠标设置。既有 UI 定时器为 50 ms，实际单击提交还受采样和系统调度影响；200 ms 是判定阈值，并非所有负载下的墙钟响应上限。

Windows 仍可能在应用短窗口结束后发送 `WM_LBUTTONDBLCLK`。这类消息现在被当作第二次普通按下处理：第一次单击如果尚待定则先确认，第二次单击继续独立判定；如果第一次已经由定时器确认，也不会额外触发全屏。短窗口内的有效双击仍只切换全屏，不向播放后端发出播放／暂停命令。

底部按钮继续即时响应，标题栏和播放列表分隔条保留各自的双击操作；长按倍率沿用 2.2.4 修复。新检查覆盖播放／暂停状态、短窗口前后、先到定时器和先到第二次按下的两种顺序，以及独立点击、连续双击、EOF、焦点取消和快捷键优先等既有情况。验证采用受控窗口消息与真实播放核心，另记录实际经过时间的单击提交；未使用桌面物理鼠标自动化。

本版采用原有固定 UCRT 工具链。运行载荷仍为 111 个文件，仅 EXE 有预期变更，不更新播放 DLL 或模型。修改前 247 个自有文件及正式 EXE、设置、列表已备份至 `build/click-response-20261101/before/2.2.4-recovery.zip`，本次 60 个用户文件有逐项保护清单。
