# 较小的新多语种翻译模型：来源核验与本机实测

日期：2026-10-28。目标：寻找比现有 Hy-MT2 Q4、Index-Translate Q4 更小，优先照顾日中、中日、英中、中英，并覆盖德法等语言的实时字幕翻译候选。

## 选型结果

当前优先保留 **小米 MiLMMT-46-1B-v1.0** 作为轻量候选：

- **Q4_K_M：768.72 MiB**，比现有 Hy-MT2 Q4 权重小 **28.86%**，比 Index Q4 小 **38.57%**。本轮整句文本翻译中位数 **3.078 秒**，推理进程峰值工作集 **856.43 MiB**。优先考虑这个版本，细节保留相对好一些。
- **IQ4_XS：684.90 MiB**，分别小 **36.62% / 45.27%**；中位数 **2.971 秒**，工作集 **773.19 MiB**。适合体积优先的实验选择，但确认出现更多数量、时间与日文指令细节错误。
- 两者都有实质误译，尚不能作为“翻译质量接近原模型、且播放与识别同时运行仍能实时”的验证结论。尤其是中日方向仍需扩大实际字幕评估。
- 本轮未找到已经在本机验证合格的 **500 MiB 以下**通用多语种字幕方案。官方 Hy-MT2 1.25-bit 最接近这个体积目标，但当前项目引擎加载失败。

研究文件位于 `build/small-translation-20261028/`。本轮没有修改播放器源代码、安装包或模型列表。候选尚未安装到播放器模型目录。

## 模型本身的新旧与来源

[MiLMMT 官方模型卡](https://huggingface.co/xiaomi-research/MiLMMT-46-1B-v1.0)列出 46 种语言，包含日、英、简繁中、德、法。它以 Gemma3-1B 为基础，进行了 143B token 持续预训练、翻译监督训练、强化学习和模型合并。基础模型的年代与翻译权重的训练年代应分别看待。

v0.1 权重仓库创建于 2026-01-29；本轮选择的 v1.0 仓库创建于 **2026-08-05**。其[论文于 2026-08-11 首发](https://arxiv.org/abs/2608.10812)，说明了 GRPO 与 SFT/RL 权重插值。这是新的翻译训练版本，符合本次“有实质训练，而非仅维护或重新打包”的筛选口径。模型使用 Gemma 许可证。

本机测试使用 [mradermacher 的社区 GGUF 转换](https://huggingface.co/mradermacher/MiLMMT-46-1B-v1.0-GGUF)，不是小米官方发布的量化文件。官方原权重约 2.00 GB，不应把这个大小与量化文件混用。2026-10-28 API 快照中，官方模型月下载量为 480、25 赞，GGUF 仓库月下载量为 837、1 赞；这些是使用热度线索，不能代替质量检验。

## 本机实测方法和范围

- CPU：Windows 硬件注册表确认 **Intel Core i5-7200U**，4 个逻辑处理器；可见物理内存约 **7.89 GiB**。CIM 清单查询被系统拒绝，改用只读注册表和 `GlobalMemoryStatusEx` 获取硬件信息，见 `research/host.json`。
- 使用项目已经固定的 **llama.cpp b11889 Windows x64 CPU** 推理程序，SHA-256 为 `049243ee4986362abecbe70b1a2ac1457d01bc4dc6178f3a3a46d9d199f57022`。所有模型依次运行，CPU 1 线程、上下文 1024、无 GPU offload、禁用 repack 和无限缓存。
- 题目在推理前写入 `research/translation-cases.json`：英中、中英、日中、中日各 8 条，覆盖交通指令、否定、改期、数量、关系、对话、人名、条件；另有德中、法中、中德、中法各 1 条，共 **36 条**。
- 五个完整测试版本都跑这 36 条，温度 0。MiLMMT 使用作者要求的源语言/目标语言模板与原始 completion 接口；其他模型使用项目现行的翻译提示语。没有把 MiLMMT 当作普通聊天模型套用默认对话模板。
- 统计从本地文本请求开始到完整译文结束的耗时；P95 使用 nearest-rank。工作集是**推理进程**的峰值，包含映射权重驻留页；private bytes 不能代替它表示全部内存消耗。
- 这些耗时没有包含语音识别、等待断句、播放器负载或字幕绘制。题目中的 4/6 秒 budget 是预设到达间隔，用于探索，不能当作真实音频时长、RTF 或实际字幕实时率。
- 调用完成与翻译正确分开判断；以下错误来自人工逐句事实检查，没有生成泛化准确率或把小样本包装成公开榜单成绩。

## 同题对照

以下每行均完成 36 条文本推理。数值只代表本轮单次串行运行。

| 模型 | 权重 MiB | 整句中位数 | P95 | 峰值工作集 MiB | 本轮判断 |
|---|---:|---:|---:|---:|---|
| 现有 Hy-MT2 1.8B Q4 对照 | 1,080.59 | 3.813 s | 5.531 s | 1,207.60 | 多数事实更稳，但也有日中漏译与不自然表达 |
| **MiLMMT 1B Q4_K_M** | **768.72** | **3.078 s** | **4.828 s** | **856.43** | 较小的新专用候选；建议优先评估 |
| MiLMMT 1B IQ4_XS | 684.90 | 2.971 s | 4.831 s | 773.19 | 再省约 84 MiB，细节错误增多 |

现有 Index Q4 的权重大小为 1,312,164,352 字节，约 1,251.38 MiB；本轮用它作存储体积比较，没有重新执行 Index 推理，故主表未列旧性能数字。

MiLMMT 的四个主要方向的整句中位耗时：

| 方向 | Q4_K_M | IQ4_XS |
|---|---:|---:|
| 英 → 中 | 2.768 s | 2.638 s |
| 中 → 英 | 3.277 s | 2.923 s |
| 日 → 中 | 3.218 s | 3.075 s |
| 中 → 日 | 3.454 s | 3.091 s |

这组单次结果不能证明 IQ4_XS 稳定地比 Q4 快。两者的 P95 接近，Q4 的最长一条为 6.200 秒，IQ4_XS 为 5.302 秒。

## 真实输出中的取舍

**MiLMMT 的可取之处：** 两种量化均正确处理了多数“更新完成前不要关机”“不要按红色按钮、按蓝色两次”“山田明早十点在东京站见李明”等英中、中英、日中、中日句子。四条德法方向也确实执行了推理，但样本不足以概括德法能力。

**Q4_K_M 确认的细节问题：**

| 题目 | 输出与问题 |
|---|---|
| 日 → 中：会議は午後3時から午後4時半に変更されました。遅れないでください。 | “会议时间已改为下午3点至下午4点半……”；把改期译成了时间区间。 |
| 英 → 中：We booked two rooms for three nights and will arrive after midnight. | “我们预订了两间房间，入住时间为三天……”；三晚变成三天。 |
| 中 → 日：我们预订了两间房，住三晚，午夜后到。 | “…夜通しの時間には到着しました。”；未正确保留“午夜后到达”，且表达不自然。 |

**IQ4_XS 另有更明显的错误：**

- 同一住宿句英译中漏掉“三晚”；日译中把三晚改为三天、“午夜后”改为“零点左右”。
- 日译中交通句“次の信号を左に曲がってください。”译为“请左转进入下一条路口”，丢失信号灯信息。
- 法译中将 `reportée` 译作“提前”；中译法把会议新时间 **16:30** 改为 **15:30**。
- 中日条件句仍有不自然表达。这说明小模型在用户重点关心的日文方向还需要扩大测试。

**较大的现有 Hy-MT2 Q4 也有失败案例：** 同一个日文交通句译成“请向左转弯，进入下一个路口”，同样丢失了信号灯。不能把所有问题都归因于量化。它在本轮住宿晚数、午夜后到达等句子中保留的事实更完整。

## 进一步压缩 Hy-MT2 的结果

### 标准 GGUF 压缩版本

1. [mradermacher IQ2_XS](https://huggingface.co/mradermacher/Hy-MT2-1.8B-i1-GGUF)：633,078,496 字节，603.75 MiB。完整哈希验证后，本机首条短句产生重复、指令回声与无关内容，直到 **160 token 上限**，耗时 **49.074 秒**。第二条进行中停止了本研究进程；只计 1 条完整输出，不属于 36 条完成测试。`results.json` 的连接关闭错误由这次主动停止造成。
2. [Unsloth UD-IQ2_M](https://huggingface.co/unsloth/Hy-MT2-1.8B-GGUF)：722,666,176 字节，689.19 MiB。完成了 4 条交通短句试测，中位耗时 **4.300 秒**、工作集 **812.60 MiB**。日译中“请将信号转向左侧”改变了动作对象；中译日把普通信号灯具体化为红灯。按本次日文优先的目标，没有继续把它作为首选候选。

结论限于这些具体文件、当前推理版本与参数，不能推导出所有低位量化都不可用。低位格式的解码开销也可能抵消文件变小带来的收益。

### 官方 1.25-bit：已做完整文件加载实测

[腾讯官方 1.25-bit 文件](https://huggingface.co/tencent/Hy-MT2-1.8B-1.25Bit-GGUF)仅 **461,860,800 字节 / 440.46 MiB**，比当前 Hy Q4 小 59.24%。本轮已完整下载，SHA-256 与上游一致：`cc497fe8f033b52b3b8b00a7669e9661435432f9d4cd43f7ed24400c01507a93`。

使用项目当前 b11889 引擎加载时，服务在 ready 之前退出，未执行任何翻译：

```text
gguf_init_from_reader: tensor 'blk.0.attn_k_norm.weight' has offset 203154464, expected 203277344
gguf_init_from_reader: failed to read tensor data
server_run_i: exiting due to model loading error
```

官方模型卡注明需要 [STQ 内核 PR #22836](https://github.com/ggml-org/llama.cpp/pull/22836)。本轮 GitHub API 快照确认该 PR 为 open、未合入，标题明确包含 ARM NEON 内核。上面的实测证明**这个完整文件不能被项目当前引擎直接加载**；它不证明模型翻译质量差，也不证明适配内核后仍无法在 x86 运行。当前没有该量化版本在本机的翻译速度、质量或字幕实时性数据。

官方 2-bit 版本约 572.71 MiB，模型卡也要求另一套特殊量化支持；[PR #19357](https://github.com/ggml-org/llama.cpp/pull/19357) 的本轮快照同样未合入。该文件本轮没有完整下载或运行。不能把官方 ARM/手机性能结果当成本机 Intel 实测。

## 其他筛选结果

- [Qwen3.5-0.8B](https://huggingface.co/Qwen/Qwen3.5-0.8B)：新系列与低体积成立，本机速度也最好，但本轮出现日译中仍输出日文、漏掉交通灯、改期错误与中译法生成异常小时数等问题。
- [LFM2.5-1.2B](https://www.liquid.ai/blog/introducing-lfm2-5-the-next-generation-of-on-device-ai)：2026 年进行了实质扩展预训练与后训练，官方 QAD 也有价值；本轮把两间房译成三间，中译德还反转了红蓝按钮指令。厂商在其他硬件上的速度不代表这台机器。
- [OmniTranslate 1.1](https://huggingface.co/MihaiPopa-1/OmniTranslate-1.1)：0.6B 的 Q4 约 378 MiB，覆盖语言的宣传很广；作者同时明确提示其仍为实验模型，准确翻译场景不适用。本轮读过训练与使用说明，未为它额外下载权重或声称已实测。
- [TranslatePsy-AfriSLM 0.8B](https://huggingface.co/qvac/TranslatePsy-AfriSLM-0.8B)：有 2026 年翻译训练，但核心目标是非洲语言；亚洲/欧洲语言混入训练主要用于保留能力。没有将非洲语言的评测优势移用到日中、中日。
- QuickMT 等部分 2026 年量化包，其原始对应权重已在 2025 年发布；旧 NLLB、M2M100、OPUS 也不作为“2026 新模型”推荐。

## 接入判断与证据

如果下一步做播放器试验，优先顺序为 **MiLMMT 1B Q4_K_M → IQ4_XS**。当前 `src/caption_translation.cpp` 使用通用目标语言提示，MiLMMT 需要作者专用的源/目标语言模板；把权重文件直接替换成 MiLMMT 不构成完整适配。

在加入正式安装列表之前，还需按实际 ASR 分句输入检验翻译，并运行播放、识别、翻译联合负载，确认长时间队列不会积压，取消/seek/切换语言后不会显示过期译文。上述事项没有在本轮模型搜索中宣称完成。

可复核证据：

- `build/small-translation-20261028/summary.json`：各轮耗时、工作集、参数、具体事实错误与模型/引擎哈希。
- `build/small-translation-20261028/downloads.json`：固定源版本、文件字节数与上游 SHA-256。
- `build/small-translation-20261028/translation-runs/*/results.json`：每条源文、原始译文与耗时；各目录 `server.log` 是真实原生推理日志。
- `build/small-translation-20261028/research/`：官方模型卡、元数据、PR 状态与主机信息快照。
- `build/small-translation-20261028/evidence-sha256.json`：上述结果与日志的校验清单。

所有本轮启动的研究推理服务均已退出；没有接管用户正在使用的播放器窗口。
