# Lumen Player 1.5.1 连续拖动修复验收

2026-10-19；Windows-10-10.0.19045-SP0；Intel Core i5-7200U，2 核 / 4 线程。

## 问题与修复

1. 1.5.0 可确定性复现：暂停状态拖动后，异步定位完成，但进度刷新只在播放时采样，松手时画出的旧进度可能一直保留。基线日志 `seek-baseline.log` 在第 5 项断言后失败；1.5.1 改为暂停时也检查位置与定位完成状态，并在未完成时显示最新请求位置。
2. 系统路径原先用一个布尔值处理多个异步定位，较早完成回调可以提前解除定位等待。现在只提交一个系统定位，后续请求覆盖待提交目标；最后一个目标得到完成回执后再落实当前播放/暂停意图，字幕采集也等待最终位置。
3. 软件路径记录请求与应用序号，新请求到达时立即废弃旧帧，避免旧帧等待阻碍后续定位；读帧前后和完成时核验代次。过期结果不能回写最新位置或误触发解码错误。保留拖动时的真实画面与短音频预览。
4. 实时字幕在读取、重新定位、提交音频和 EOF 通知时检查拖动、定位和代次状态；阻塞读取/定位不再占用 UI 的字幕交付锁。过期读取失败不会关闭新一轮字幕，定位前的音频前置数据会裁掉，恢复识别从最终目标开始。
5. 设置明确注明优先解码在下次打开时生效；“系统播放”注明实际软硬解由 Windows 决定。系统路径测试通过不代表已用 GPU 工具确认实际硬解。
