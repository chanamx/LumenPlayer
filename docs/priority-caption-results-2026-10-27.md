# 日语、英语、中英/中日优先的字幕模型实测

日期：2026-10-26 开始，2026-10-27 完成。本轮沿用用户顺序：日、英、中英、中日、基本通用、德、法。中英和中日按双向文字翻译测试。实验目录为 `D:\LumenPlayer\build\priority-caption-20261026`。

本机结论：日语优先保留 Moonshine v2 Tiny；英语 Tiny 优先响应速度，Small 配合 1 秒更新间隔可作为更重视文字质量的可选配置。小型多语种翻译默认项仍未找到同时达到本轮语义要求和本机资源目标的候选。LFM2.5-350M Q8 很快，但有严重错译；Hy-MT2 与 Index 保留关键语义明显更好，继续列入中配以上硬件选项。本轮没有据小样本结果切换正式模型。

## 实测范围和方法

本机是 Intel Core i5-7200U，2 核 4 线程，可见物理内存 7.887 GiB。85 次 ASR 运行均启动全新进程，按真实时间每 0.2 秒送入音频；总计重复测试音频 1041.466 秒。这不是 85 段不同片源。

新增的不同公开音频有 32 段：日语 Common Voice 12 段、ReazonSpeech 8 段，以及英语 LibriSpeech 小型测试集 12 段，共 231.809 秒。另有 9 个派生输入：日语连续拼接 116.539 秒、英语连续拼接 139.270 秒，日英各 8 秒静音与低电平高斯噪声，以及三个 10 dB 信噪比语音样本。拼接流包含不同原片段及 0.8 秒间隔，不是自然连续会话；派生样本不算新增独立片源。

原音频、标准化音频、参考文本、公开数据集修订、源文件/标准化文件 SHA-256、转码参数均已保存。数据集固定使用开头的指定小子集，没有根据识别效果挑选片段。公共测试音频可能与模型训练集重合，也未覆盖足够口音、说话人和内容领域；不能把结果作为全语料准确率或普遍稳定性。

ASR 使用 moonshine-voice 0.1.5 原生 C API、当前播放器 ORT 1.28.2，强制单线程 CPU。通过配置检查 API 返回值，完整读取字幕行 ID、更新和结束状态，保留每次修改的音频/墙钟时序。连续输入缓存已结束字幕行，防止只看到最新段落。每批运行绑定探针源码 SHA-256 和源码快照。

日英原生运行均记录了 tokenizer 缺少 byte fallback block、改用最长匹配编码的警告，完整 stderr 已保留。结果因此限定为本轮原生运行时、模型包和配置的实际表现；尚未量化该回退对准确率的影响，不把所有错词都归因于模型架构或推广为其他后端的表现。

翻译测试共 104 次请求：LFM2.5-350M 先做 8 句试测，再做 32 句主矩阵；Index、Hy-MT2 各做同样的 32 句。主矩阵为英→中、中→英、日→中、中→日，各 8 类：日常指令、否定、时间变更、数字/住宿、按钮关系、对白、人名地点、条件句。关键语义约束在推理前已保存。测试使用原生 llama.cpp b11889、CPU 1 线程、无重排、受限缓存；LFM 使用作者推荐的低温采样。完整参数、种子、模型/运行时哈希及原始输出均保留。

CPU RTF 在本报告中指“进程 CPU 秒数 / 音频秒数”，不是整机 CPU 百分比。首字时间从模型已加载后按实时速率输入音频开始计时；不是点击按钮后的冷启动时间。私有内存与工作集是整个探针/服务器进程的两种不同指标，不能相加。翻译耗时从完整文字已经可用开始，尚未包含语音断句、识别、视频播放和字幕上屏耗时。

## 日语识别

同样 20 段、390 个参考表面字符的对照如下。表面字符统计保留“わたし/私”“八/8”等书写差异，所以字符差异不全是听错，不能直接当成真实错义率。

| 项目 | Tiny，0.5 秒更新 | Small，0.5 秒更新 |
| --- | ---: | ---: |
| 模型文件合计 | 32,319,961 B，约 30.82 MiB | 121,803,780 B，约 116.16 MiB |
| Common Voice 12 段表面编辑数 / 216 字符 | 33 | 31 |
| ReazonSpeech 8 段表面编辑数 / 174 字符 | 63 | 63 |
| 总表面编辑数 / 390 字符 | 96 | 94 |
| 有语音但最终为空 | 1 / 20 | 1 / 20 |
| CPU RTF 中位数 | 0.080 | 0.252 |
| 已加载后首字中位数 | 1.301 秒 | 1.401 秒 |
| 本组最大处理落后 | 0.258 秒 | 0.714 秒 |
| 结束前私有内存中位数 | 113.08 MiB | 304.92 MiB |
| 结束前工作集中位数 | 97.33 MiB | 208.20 MiB |

Small 修正了“大橋さん”和棒球解说中的部分名字/词语，也出现 `YouTube`、`なるほどなるほど` 等参考文本中没有的内容。两种规格都漏掉了儿童歌声片段“ピカピカブ”，对照片中的“写真”等词仍有识别错误。Small 的总体提升没有与约三倍 CPU 开销和明显增加的内存形成足够有力的交换关系。

116.539 秒连续拼接流中，Tiny 表面编辑数为 127/390，Small 为 101/390；Small 在这个场景确有改善，不能据单句汇总说它没有价值。但两者仍有错误和新增词。Tiny 在电视片段切换附近出现反复的“肘を”等内容；Small 也有无关词和漏句。Tiny 此次 RTF 为 0.074、私有内存 134.46 MiB；Small RTF 为 0.254、私有内存 332.80 MiB。能跟上输入，不等于字幕内容已经可靠。

补测 Tiny 的语音检测阈值 0.3：同样 8 段 ReazonSpeech 表面编辑数由默认 0.5 的 63 增加到 79，歌声仍为空。各 8 秒静音及低电平噪声没有产生字幕；这两类短空输入通过，不代表所有背景音乐均不会误触发。本轮不据此降低默认阈值。

## 英语识别

Tiny 在 12 段独立输入、303 个参考词中产生 37 个字面编辑，CPU RTF 中位数 0.267，已加载后首字中位数 1.325 秒，私有内存中位数 144.08 MiB。字面词统计包含 Mr./Mister 的差别，因此不把全部编辑数都解释为听错。

同样前四段的配对对照：

| 配置 | 字面编辑数 / 83 词 | CPU RTF 中位数 | 最大处理落后 | 私有内存中位数 |
| --- | ---: | ---: | ---: | ---: |
| Tiny，0.5 秒更新 | 11 | 0.267 | 1.723 秒 | 144.87 MiB |
| Small，0.5 秒更新 | 4 | 0.868 | 2.505 秒 | 353.51 MiB |
| Small，1 秒更新 | 4 | 0.573 | 1.063 秒 | 355.39 MiB |

Small 修正了 Quilter、grave doubts、similes 等词，但仍有人名和地名错误。将 Small 的更新间隔放宽到 1 秒，在这四段上保留相同最终文字，并降低了 CPU 开销；首次输出的个别样本也更晚，不能简单写成“间隔变长而延迟全面更好”。

139.270 秒相同连续拼接流的补测：

| 配置 | 字面编辑数 / 303 词 | CPU RTF | 首字 | 最大处理落后 | 私有内存 / 工作集 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Tiny，0.5 秒更新 | 35 | 0.294 | 1.292 秒 | 1.557 秒 | 169.06 / 137.23 MiB |
| Small，1 秒更新 | 17 | 0.529 | 2.579 秒 | 2.495 秒 | 381.37 / 260.41 MiB |

因此 Tiny 继续优先响应速度；Small + 1 秒更新值得保留为偏重文字质量的可选档。Small 的平均处理能力能跟上本组输入，但仍有约 2.5 秒峰值落后，且没有在同次测试中叠加真实视频播放负载。不能据这些结果保证它在所有影片上都保持同样实时性。

## 中英与中日翻译

同样 32 句主矩阵的测量结果：

| 模型 / 当前配置 | 首字中位数 | 整句完成中位数 | 最大整句耗时 | 末次私有内存 / 工作集 |
| --- | ---: | ---: | ---: | ---: |
| LFM2.5-350M Q8_0 | 0.661 秒 | 1.260 秒 | 2.312 秒 | 74.27 / 414.72 MiB |
| Index-Translate-2B Q4_K_M | 2.083 秒 | 4.274 秒 | 5.543 秒 | 352.38 / 1349.32 MiB |
| Hy-MT2-1.8B Q4_K_M | 2.044 秒 | 3.758 秒 | 6.280 秒 | 188.48 / 1207.10 MiB |

这是各自完整输出已经结束的时间，不以第一个 token 代替整句延迟。不同句子、目标语言和长度会改变排序；本轮四方向/较长句的中位数不能与前轮不同输入的 20 句中位数直接混为一组。Index/Hy-MT2 仍保留为中配以上选项，本轮没有给出其最低推荐硬件规格或当前播放器整条链路的实时保证。

LFM2.5-350M 的 379,217,632 字节 Q8 文件较轻，HF 和魔搭官方 LiquidAI 命名空间公布的 SHA-256 一致，实际文件完整校验通过。选用 Q8 是为了减少把较小规格错误全部归咎于 4-bit 量化的可能，仍不能据单个后端/提示词的结果宣称其所有用途都失败。

本轮足以否决这组 LFM 翻译配置作为默认项的错误包括：

- “更新完成之前，不要关闭电脑”被译成 `After the update was completed, do not close your computer.`；日语相同约束也被译成“更新完成后”。
- “会议从下午三点改到四点半”被译成三点开始、四点半结束，改变了时间变更关系。
- “午夜后到”出现“中午到”“延迟退房”，中→日还直接返回原中文。
- 蓝色按钮按两次被译成红色两次、蓝色一次；人名时间句出现 `Tomaya`、`October 10th`，野餐出现 dinner/派对。

Index 和 Hy-MT2 对上述多数否定、数字、人物及条件关系的处理明显更好，但也存在要保留的反例：Index 的日→中把三晚译成三天，并保留了未译的“大丈夫”；两种模型在中→日“关闭电脑”中都出现了较直译的“闭上电脑”表达。Hy-MT2 的日→中路口指令也改动了信号灯定位。这里使用未盲评的人工语义检查，没有据这 32 句制作通用准确率排行榜。

全部 96 条主矩阵输出在 [逐句对照文档](D:/LumenPlayer/docs/priority-translation-comparison-2026-10-27.md)，精选问题在 `build/priority-caption-20261026/semantic-review.json`；每个词都可对照原始结果复查。

## 根据当前优先级的安排

1. 日语：Tiny 继续作为当前机型优先接入候选，下一轮应围绕真实日语影视/对话、多说话人及背景音乐漏句，不以放大规格作为默认解决办法。
2. 英语：保留 Tiny 的低延迟配置，以及 Small + 1 秒更新的质量可选档；后者仍需真实视频负载联合测试。
3. 中英、中日：保留 Index/Hy-MT2 的中配以上档位。轻量默认翻译器尚无足够证据可定案，不能用 LFM 小模型的速度抵销关键错义。
4. 基本通用：语言列表只是候选入口，不代表字幕识别与翻译都通过；230M 和 CAT 的未测状态单独记录。
5. 德、法：本轮没有新增这两种语言的音频成绩；此前 EuroNano 德/法文字翻译与德语链路结果仍按原报告范围保留，不扩大为中日覆盖。

中文现用识别模型维持既有质量基线。此前在线获取中文权重的实际下载、完整哈希和播放 PCM 识别证据见 [前轮渠道/原生播放报告](D:/LumenPlayer/docs/verification-and-model-options-2026-10-26.md)。模型下载源回退应要求同一模型、同一版本、同一文件大小/哈希，并在所有辅助文件齐全后启用；不能在下载不完整时把模型显示为可用，也不能用另一模型的同名文件拼接替代。

## 证据与边界

- 汇总：`build/priority-caption-20261026/priority-summary.json`、`asr-summary.json`；逐句结果、时序和资源在 `asr-runs/` 与 `translation-runs/`。
- 输入与模型来源：`research/audio-inputs.json`、`derived-inputs.json`、`translation-cases.json`、作者页快照及 HF/MS 元数据。失败下载记录保留在研究目录。
- 85 次识别进程全部正常退出，无资源/超时保护触发；最低可用提交空间约 4.853 GiB。4 个翻译服务器实例均已退出；这些计数不包含失败下载为成功推理。
- 正式源码、发布程序、依赖、当前模型和既有设置/列表共 28 项基线，最终重新核对；完整检查与源文件绑定见 `final-validation.json` 和本轮清单。
- 本轮模型测试使用独立原生探针，没有验证新模型与真实影片、完整发布 EXE 鼠标操作及最终上屏的联合体验。首字、CPU、内存或短静音通过不能替代这项验证。
- 原状态复现结论仍按 [前轮报告](D:/LumenPlayer/docs/verification-and-model-options-2026-10-26.md) 的证据范围：软件解码标签正常；内嵌字幕的 CC 指示不一致在生产函数原生测试窗口中已复现。独立发布 EXE 的完整鼠标流程尚未完成，不能把两者混为同一种 UI 实测。
