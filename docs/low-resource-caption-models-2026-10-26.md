# LumenPlayer 当前机器的轻量字幕模型补充研究与实测

核验日期：2026-10-26。机器：Intel i5-7200U，2 核 / 4 逻辑处理器，约 8GiB 内存。用户已明确：Index-Translate、Hy-MT2 等 1.8–2B 翻译模型保留为中配以上可选档，当前机器继续优先寻找更轻的实时方案。

本轮结论是：**找到有实际速度优势的英法德小型专用翻译模型，但还没有得到覆盖中、英、日、法、德且质量与资源都达标的统一默认方案。** Index / Hy-MT2 的分档写入研究候选表，正式播放器尚未新增这些选择项。

## EuroNano 真机翻译结果

采用作者当前 QVAC 原生 Bergamot CPU 路径，测试依赖仅安装在项目实验目录。运行库为 translation-nmtcpp 0.21.1、fabric 0.22.0、Bare 1.36.0；三个官方包的完整缓存均独立通过 npm SHA-512 校验。进程限制在一个逻辑处理器，不把进程亲和性限制表述成已证明库内部仅有一个线程。

下表的延迟从完整源文本已准备好开始，到整句译文返回结束。私有提交与工作集是不同指标；权重大小也不代表整个功能的安装体积。

| 配置 | 整句中位耗时 | 首次方向请求最大耗时 / 全轮最大 | 峰值私有提交 | 峰值工作集 |
| --- | ---: | ---: | ---: | ---: |
| Tiny，欧语→英语单方向，beam 4 | 40.3ms | 134.1ms | 396MiB | 198MiB |
| Base，欧语→英语单方向，beam 4 | 61.1ms | 253.8ms | 519MiB | 367MiB |
| Base，双方向同时加载，beam 4 | 73.2ms | 312.6ms | 1000MiB | 610MiB |

单方向测试为 6 个法/德到英语用例各重复 3 轮；双方向测试为 16 个用例重复 2 轮。单方向 Base 去掉首次请求后的中位约 60.0ms；双方向约 71.9ms。Tiny 单向权重为 17,141,227 字节，Base 为 42,993,131 字节；双向需要两套权重和相应词表。Base 单方向的内存仍明显高于现有约 220MiB 私有提交的中文识别器，不能称作资源代价完全相同。

Base 的普通句、否定与数值保留比 Tiny 更有希望，例如正确保留了 120 欧元、不含早餐、两间房三晚、午夜后，以及把 river bank 译为河岸。beam 4 的法语长句也保留了“请保留预订”的意思。但典型影视习语仍有明显缺陷：`The drinks are on the house tonight.` 的英法、英德输出都未表达“免费”。部分普通句也有语法和措辞问题。因此当前定位是**英法德轻量实验选项**，尚未达到完整影视字幕默认翻译质量。

兼容性排查有两个实际发现：

1. 旧版 Bergamot WASM 加载随模型提供的 shortlist 后出现严重异常文本；使用同一组已校验权重、关闭 shortlist 后恢复可读译文。该现象只定位到这个组合，不推断所有运行库或这些模型本身均有同样问题。
2. 该多语模型使用目标语言标签。字幕含多个句子时，旧路径的自动分句可能让后面的句子丢失标签，导致第二句漏译。原生测试采用逐句携带标签的输入方式，保留完整的两句输出。正式接入也需要处理这件事。

WASM 双向 Tiny 峰值私有提交约 1.55GiB，Base 约 2.20GiB；调整 workspace 未在该版本中获得占用改善。最终候选判断使用上表原生结果，未把 WASM 的异常译文当成模型全局准确率。

## 按播放速度送入的识别→翻译链路

使用已验证的 Moonshine v2 German Tiny、播放器当前 ONNX Runtime 1.28.2，以及 EuroNano Base 单向欧语→英语，按每 200ms PCM 块送入。只有当前字幕行发生文本变化时才调用翻译。翻译进程限制在一个逻辑处理器，识别运行库使用其原生单线程配置。

连续执行了两次 60s 调度测试，每次 80 个翻译更新。第二次补充明确的音频时钟打点：

- 模型准备好后，从开始送入音频到第一条英语译文：**918ms**。
- 从最新 PCM 块的播放时刻到译文返回的处理落后量：中位 **261ms**，P95 **602ms**，最大 **768ms**。
- 60s 音频的识别与同步翻译处理在约 **60.16s** 完成，没有出现随播放长度持续增长的队列积压。
- 第二轮两个进程合计峰值私有提交 **671MiB**；采样工作集之和 **442MiB**，共享页可能重复计数。第一轮对应为 673MiB / 447MiB。
- 第二轮识别进程累计 CPU 约 13.78s，翻译约 10.45s，合计约 **0.404 CPU 秒 / 音频秒**。这是累计 CPU 时间比例，不是整机 CPU 百分比。

该输入由一个约 2.75s 的德语片段重复构造，是调度与资源测试，不是多说话人或多片源质量测试。运行库记录了德语 tokenizer 退回最长匹配编码的提示；输出中也确有德语错词，译文继承了原文错误。部分 200ms 块处理会超过当前块长，最大约 0.77s，随后能够追上。因此本结果证明这条隔离组件链路有实时处理余量，仍需更广的语音与对白质量验收。

这不是播放器 UI 内的正式接入，也没有同时运行高码率视频渲染或 GPU 负载。918ms 以模型准备好后的音频开始为基准；启用字幕时的冷加载耗时另行记录。

## 更小的 Qwen 也没有通过质量筛选

已完整下载 563,036,064 字节 Q4_0 文件，校验 SHA-256 为 `57d1997790d1744fba5b40a7317df71ea5e2acee28c47e78f0cce39c0703f8cf`。CPU 1 线程，关闭思考，控制上下文及缓存；分别测试贪心参数和作者建议的非思考文本参数。两轮各 20 个翻译用例。

| 参数 | 首字中位耗时 | 整句中位耗时 | 整句最大耗时 | 峰值私有提交 / 工作集 |
| --- | ---: | ---: | ---: | ---: |
| 贪心 | 1.398s | 2.091s | 3.416s | 348MiB / 669MiB |
| 作者建议 | 1.361s | 2.175s | 3.425s | 348MiB / 669MiB |

实测错误包括：贪心下 14:30→15:00、两间房→三间、午夜后→午夜前、十二号出口→三号，以及一条应译中文的日文基本原样输出。作者参数改善了其中部分例子，但出现十五分钟→十分钟、“更新完成之前不要关电脑”变成“更新完成后不要关电脑”，14:30 错误也仍存在。习语和河岸歧义同样未解决。

因此暂不将**本轮被测 Q4_0 和这两套运行参数**列为默认字幕翻译方案。这个判断不等于断言所有精度、任务提示或整个 Qwen 家族都会如此。模型更小带来的占用优势不足以抵消这些关键语义错误。

## 法语识别缺口仍在

Moonshine-Tiny-FR 的 int8 编码器与合并解码器总计约 27.1MiB，词表另计。用生产 Sherpa C API / 当前 ORT 完成三个片段的全文识别和 4s 分块识别，共六次独立运行；又使用已安装 ORT 1.24.1 做三个无缓存解码诊断，未使用生产探针的缓存逻辑及尾部填充。

这组导出权重的识别文本在两条路径中都出现严重错识、短输出与重复。全文三个固定片段共 35 个参考词、31 个编辑错误；该小样本不能外推成所有法语语音的模型准确率。4s 分块还有更严重的重复。当前内存约 90–95MiB 私有提交、102–106MiB 工作集，说明资源较轻，但质量未过关；分段第一条输出约 4.38–5.41s，也不能当作亚秒原生流式识别。

原始模型卡明确称该模型为 proof of concept，并说明读书语音领域、重复及幻觉的限制。当前结论只针对已测导出组合；尚未测试其 FP32 原始权重，未据此否定所有后续法语微调。

## 下载渠道复核

- **EuroNano HF**：Tiny / Base 两方向权重、词表与 shortlist 全部取得；大文件按作者 HF LFS SHA-256 校验。作者 GitHub 页面与说明已读取；进一步 GitHub API 文件树请求遇到公开额度限制后停止，没有继续重试或绕过。`qvac/TranslatePsy-EuroNano` 魔搭同名路径返回 404；本轮未确认可替换的作者镜像。
- **Qwen GGUF HF + 魔搭**：ggml-org 两站 Q4_0 / Q8_0 / BF16 的体积与 SHA-256 均一致。HF Q4_0 已完整下载并校验；魔搭实取首 1MiB，字节与完整 HF 文件前缀一致。魔搭属于目录、哈希及小范围下载验证，不能表述为第二次完整模型下载。
- **Qwen 原始权重**：作者 HF 与魔搭原始 safetensors 体积、哈希一致，为元数据核验，本轮未再下载 1.75GB 原始文件。
- **现有中文模型**：前轮已完成 GitHub 官方归档、HF、魔搭三个来源的完整验证；魔搭词表不完全相同的限制仍保留，参见前轮报告。不要把其结果借用给这些新模型。

初始 Web Composite Search 实际运行了多个引擎，但代表查询出现大量无关结果；本报告不把引擎返回成功计作已找到有效模型。Sn Search Code 的 HF 搜索、作者页面、公开模型 API 与实际文件校验共同构成候选依据。HF 大文件下载多次有界续传后才完成，错误记录与最后完整校验均保留。

## 当前建议与证据范围

当前中文识别继续保留现有已测模型；英、日、德继续优先考察已测的 Moonshine v2 Tiny。法语低耗识别尚未补齐。英法德文本翻译优先继续验证 EuroNano Base 的按需单方向加载，补测真实对白、口语、专名、断句和 ASR 错字传播。中、日文实时翻译仍没有从这轮小模型里选出合格默认项。Index-Translate、Hy-MT2 保留中配以上可选档；Nemotron 3.5 的较大提交量也不适合作为当前低耗识别默认项。

本轮原生 EuroNano 132 次文本调用覆盖 16 个翻译用例，Qwen 40 次调用覆盖另一组 20 个用例；其中部分源句用于多个目标语言。两个 PCM 链路各 60s，共 160 次更新，复用同一个德语片段。法语为 6 次生产运行库探针与 3 个独立解码诊断。请求数不等于独立片源数。

正式代码、EXE、播放内核、现有模型与安装包的 **28 项前轮关键基线逐一核对不变**。无模型安装包仍是前轮 QA 验证构建，未在本轮切换正式分发或新增下载界面。
