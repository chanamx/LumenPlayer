# LumenPlayer 2.2.3 单击／双击互斥修复

修复视频双击先触发播放／暂停的问题。2.2.2 在第一次松开鼠标时立即切换播放状态，收到双击消息后再反向恢复；即使最终状态相同，中途也已经发出播放控制命令，片尾还有重播和定位的副作用。

2.2.3 使用已有待确认点击状态，在系统双击时限结束后才执行视频画面的单击。双击取消待定单击，只切换全屏，不调用播放或暂停，也不再回滚播放状态。底部播放键仍即时响应，第二次快速点击携带的 WM_LBUTTONDBLCLK 继续作为按钮激活处理。

确认后的单击按点击时的播放意图执行；例如用户点击暂停后，视频恰在等待期间结束，也不会变成从头重播。失焦、手势取消、切换界面／媒体以及其他明确控制会清理待定单击。普通鼠标捕获释放之后才登记待定点击，避免 ReleaseCapture 自己产生的取消消息吞掉正常单击。独立的普通视频点击仍分别确认；三连击只保留其最后一次单击。

视频画面的单击因此需要等待系统双击判定，等待上限跟随 Windows 当前设置；播放按钮和空格键保持直接响应。未新增设置项、运行依赖、后台任务或额外定时器。解码、模型和渲染实现保持本轮开始时的版本。

## 验证方法与范围

先备份并核对正式 2.2.2，再把新输入契约放在未修改的 2.2.2 生产代码上运行，成功复现“第一次松开就发出播放控制”的失败。修复后的专项使用原生 HWND 消息及计数后端，检查中途的 Play/Pause/Seek 调用，包含双击前的计时器处理，而非仅比较最终状态。按下时长在探针中受控，避免冷绘制时间被当成用户长按；这不是人工鼠标操作桌面的验收。

专项覆盖播放、暂停、EOF、模型等待、计时确认、连续双击、三连击、不同位置的普通点击、失焦／捕获取消、设置、空格、播放按钮快速连击及拖动／区域外松开。既有真实播放回归继续覆盖软硬解路径下的按钮连续点击，并按新的延迟确认契约检查真实视频及停靠播放列表中的视频区域。

本轮通过 **51 项点击专项、223 项播放控件回归、1,613 项完整播放断言**。具体运行时间、EXE 启动和安装包身份以 `build/click-fix-20261030` 的原始日志、`*.run.json`、`installer/provenance.json` 和 `validation.json` 为准。正式 EXE 在含中文和空格的隔离路径中启动，实际使用 gpu-next / wasapi，实时识别产生字幕；正常退出时丢弃 2 条未保存字幕，未自行写出字幕文件。配置和列表经测试恢复为原字节。当前版本复核：

```powershell
python -B test/finalize_click_fix_release.py --check-only
```

过程中保留了隔离探针 HWND 尺寸／按下时长修正，以及旧真实视频测试缺少第二次松开、旧停靠测试仍要求立即单击的失败记录。它们在修正测试后重新执行，不计入通过项，也没有据此调整解码或模型逻辑。

本轮未新增实体 HDR／功放、跨显示器 DPI、长片性能或全套公网协议验收；历史验证继续归属原始版本。Windows 消息依据：[双击消息顺序](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-lbuttondblclk)、[系统双击时限](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdoubleclicktime)、[捕获释放通知](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-capturechanged)。
